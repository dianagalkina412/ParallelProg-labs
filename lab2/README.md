# Lab2
Лабораторная работа №2
Модифицировать программу из л/р №1 для параллельной работы по технологии OpenMP.
Провести серию экспериментов с разным количеством потоков (1, 2, 4, 8, 12), разными размерами матриц (200, 400, 800, 1200, 1600, 2000), использовать фиксированное существующее количество вычислительных ядер, например 8.

Порядок выполнения л/р:
1. Модифицирована программа из л/р №1 для параллельной работы по технологии OpenMP. Для преодоления проблемы ограниченности памяти промежуточные результаты вычислений перенесены из стэка в кучу, что замедлило время вычислений без распараллеливания примерно в 3 раза (с 19,7 до 62,1 мс на матрице с диагональю 200), но позволило перемножать матрицы с диагональю больше, чем 200. Слегка модифицирован вычислительный цикл: добавлена промежуточная локальная переменная sum для накопления промежуточной суммы. В программу добавлена константа, хранящая количество задействованных потоков при перемножении матриц.
2. Выполнены запуски программы для разных размеров матриц (200, 400, 800, 1200, 1600, 2000), а для каждого из этих размеров - с разным количеством задействованных потоков процессора. Для каждого размера матриц сохранены сгенерированные матрицы "MatrixA.csv", "MatrixB.csv", а также результат перемножения - "MatrixC.csv". Они сохранены в соответствующий каталог (200x200, 400x400, 800x800, 1200x1200, 1600x1600, 2000x2000). Результат перемножения проверен при помощи Python-скрипта, созданного в л/р №1 (результат - достоверное совпадение). Продолжительность времени перемножения для 10 попыток и среднее значение продолжительности для каждого размера матрицы и задействованных потоков процессора сохранены в файлах DurationX.txt (X - количество задействованных потоков 1, 2, 4, 8, 12).
3. Результаты этих 30 серий запусков сведены в таблицу (Duration.xlsx), по которой составлены 2 графика:
- продолжительность перемножения квадратных матриц (мс) при распараллеливании на 1, 2, 4, 8 и 12 потоков (горизонтальная ось - размер матрицы, ряды - количество потоков);
- продолжительность перемножения квадратных матриц (мс) различного размера при распараллеливании на 1, 2, 4, 8 и 12 потоков (горизонтальная ось - количество потоков, ряды - размер матрицы).

Вывод.
Как видно из результирующей таблицы, существенная прибавка эффективности при увеличении количества потоков распараллеливания заметна у больших таблиц, в то же время на маленьких таблицах увеличение количества потоков более 4 практически не даёт прибавки эффективности, а у таблицы 400x400 мы наблюдали даже деградацию при дальнейшем увеличении числа потоков до 8 или 12. Объясняется это резким ростом накладных расходов — затрат, которые не связаны с собственно вычислениями, а идут на поддержку параллелизма. На малых объёмах данных эти издержки становятся соизмеримы или даже превышают выгоду от параллельной обработки. Таким образом, планируя распараллеливание потоков вычисления, необходимо под каждый объём вычислительной задачи подбирать оптимальное количество потоков.
